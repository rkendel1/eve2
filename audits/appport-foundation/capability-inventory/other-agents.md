# Other existing agents — code-verified capability inventory

Scope: the 19 repos cloned under shallow clones of `rkendel1/<repo>` named in the brief (plus `overlay`, empty) and `/home/user/appboundry` @ `9f84020`.
Method: read-only inspection of source (entry points, `package.json`, tool registries, `app.agent`/`capability:` declarations, AppPort `defineCapability`, HTTP routes). No tests were run. Every clone is a single shallow commit, so authorship history is not available; "last commit" is `git log -1 --format=%cs`.
Ecosystem check = grep for `@appport`, `authboundry`, `feltdb`, `feltkit`, `resolver`, `eve` in code/manifests (word-boundary false positives such as `ripgrep-resolver` ignored).

Definitions used: **agent** = model-driven loop that chooses tools. A FeltKit `app.agent(...)` with a deterministic handler (no model) is a _durable automation_, not an agent, and its repo is classed by its product.

### Triage notes (one paragraph each)

- **relationship-agent** ("Boundry Connector"): FeltKit app (`feltkit/*.ts`, React UI). It turns a request into a brief, matches people by evidence, and runs double-opt-in introductions with human-approved delivery (`_delivery.ts`: in_app / external integration / manual). Brief interpretation and matching are deterministic. It publishes `briefs.create` (`feltkit/briefs.ts:33`) and `briefs.match` (`:157`). It is not an agent despite the name. Tests: `tests/{delivery,isolation,matching,rules,workflow}.test.ts`.
- **voice-agent**: the only _Boundry-built_ model-driven agent. A FeltKit app (businesses, numbers, contacts, calls, appointments, tasks, audit, `invocations` ledger) plus a telephony gateway (`gateway/`: Twilio ConversationRelay voice + SMS, simulator, `LlmBrain` for the Anthropic Messages or OpenAI Chat protocols, `DeterministicBrain`). The model's tools are AppPort capabilities that the runtime calls as its own principal (`voice-runtime`, role `voice`). Each agent profile's allow-list is enforced in `feltkit/_authz.ts:46-63`.
- **boundry**: static corporate site (`src/build.mjs`) plus `intelligence/`, the `@boundry/intelligence` ingestion service for `boundry.event/1` (Vercel function `api/intelligence.mjs` → FeltDB application). This is telemetry infrastructure, not an agent.
- **boundry-mesh**: WireGuard mesh architecture docs plus a read-only `scripts/host-preflight.sh`. The README says "Nothing is built yet."
- **signal**: deterministic "what is important now" engine (`lib/engine/*`), with sources fetched through an SSRF guard (`lib/sources/net-guard.ts:73-89`), a browser extension, and a FeltKit backend. Caps: `signal.findings.list`, `signal.notices.list`, `signal.sources.push` (`feltkit/sources.ts:163`).
- **TaskFlow**: Linear-like issue tracker on FeltKit. Its `assistant` (`feltkit/assistant.ts:22`) is a deterministic durable handler that files follow-up issues only after `ctx.authority.decide` (AuthBoundry delegation, `:37`). It is the cleanest reference for "act for a person under revocable delegation". External agents use `/mcp` with an agent session. `@feltdb/webllm`/`@mlc-ai/web-llm` are declared but have no references in `src/` or `feltkit/`.
- **llm**: `@easy-llm/llm`, a provider-agnostic model client and router with a registry, CLI (`setup|doctor|run|route|models|proxy…`) and proxy. It is not Boundry ecosystem and offers no agent tools. It is relevant to the destination only as an alternative model router (eve has its own providers).
- **competition** ("Sitemap Intel"): FeltKit app plus a `capturer` runtime component (`gateway/capturer.ts`) that claims durable capture work and fetches competitor sitemaps on a schedule. Caps: `intel.profile|competitors|addcompetitor|schedule|capturenow`. No model use in src (web-llm declared only).
- **boundry-intel**: `@boundry/intel-registry`, the ecosystem registry (products, repos, capabilities, publishers, event acceptance) on FeltDB. It serves read-only AppPort/MCP caps (`src/capabilities.mjs:107-171`: `intel.status`, `intel.datasets.list`, `intel.events.list|get`, `intel.registry.list|get`, `intel.publishers.list`, `intel.diagnostics`).
- **atomic-agent**: full local-first CLI/TUI agent (MIT, © Atomic Bot), a fork of third-party OSS. It has browser (CDP/Playwright), OS/fs/git/shell with a command guard, web search/fetch, layered memory, scheduler, MCP client, skills, Telegram, and a llama.cpp sidecar. It has no Boundry dependencies.
- **ai-office** ("Local Office AI"): a Word/Excel/PowerPoint/Outlook add-in plus a local companion server. The agent runtime plans, proposes, applies through Office.js and verifies, using local models only (Ollama / OpenAI-compatible on loopback). It is not ecosystem.
- **desktop-agents** ("Foundry", npm name `douchat`): an Electron multi-agent workbench (AGPL-3.0, derived from ThinkAny's douchat). It has coding sessions with approvals in Git projects, group chats, routines, skills, memory, IM channels (WeChat/Feishu/Telegram), email (IMAP), local agent CLIs (Codex/Gemini/Grok), and FeltDB storage (`src/main/felt/database.ts`). It publishes a **Foundry coding AppPort contract** (`src/main/appport/contract.ts`, app id `ai.douchat.desktop`) and uses `@appport/services` API keys and `@appport/github`.
- **browser-agent-runtime**: research on small browser-local models (WebLLM), with `DecisionRuntime` reading option-token logits and a bounded DOM agent loop. Tools are `getPage` and `searchContext` only. This is an experiment.
- **boundry-maint**: package/crate release inventory and **release governance** (propose/approve with an SSH-signed statement/trigger/withdraw/abandon). It is published as AppPort app `dev.boundry.maintenance` (`src/appport/application.ts:65-120`).
- **resolver-control**: governance UI and backend for Resolver `ref://` dependency changes (propose → approve → execute through Resolver → verify). It has 31 AppPort caps. `tests/agents.test.ts` asserts that an agent "never approves, executes, or changes policy".
- **saaskit**: commercial engine (catalog, entitlements, metering, Stripe, lifecycle) with **per-agent spending authority** (`feltkit/agents.ts:1-8`: application authorization + commercial entitlement + spending policy must all allow).
- **frame**: social network where agents are participants. `scout` (`feltkit/agents.ts:16`) and `concierge` (`feltkit/tasks.ts:206`, gated by AuthBoundry `ctx.authority.decide`) are deterministic. It publishes 53 caps and `/mcp`.
- **multiplayer**: team chat with a deterministic room agent (`feltkit/agents.ts:22`, `composeDeterministic`) and a `personalos` relay agent (`feltkit/personalos.ts:35`) that forwards requests to the user's PersonalOS (PersonalOS is out of scope here).
- **overlay**: the clone contains no tracked files.
- **appboundry**: the AppPort/AppBoundry monorepo (packages `appboundry`, `-host`, `-runtime`, `-agent`, `-companion`, `-route`, `cli`; `apps/cloud-portal`, `apps/cloud-platform`; `integrations/feltdb`; `studio`). Agent-related code:
  - `integrations/feltdb/src/agent-durable-work.ts` (`FeltDb10AgentAdapter`, `FeltDbAgentDurableWork`) is the FeltDB 0.10 delegated-agent substrate: connect principal → session → durable work → authorize → admit operation → attributed mutation → provenance chain → recover/checkpoint.
  - It is exposed by cloud-portal at `POST /api/agents/connect`, `POST /api/agent-work`, `POST /api/agent-work/mutate` and `GET /api/agent-work/provenance` (`apps/cloud-portal/src/server.ts:569-591`).
  - Hosted AppPort apps are projected as MCP (`packages/appboundry-host/src/mcp.ts`, `packages/cli/src/mcp-host.ts`).
  - `packages/appboundry-agent` is an execution-host _deployment reconciler_ (pull intents → verify artifact → run container → report evidence), not a model agent.
